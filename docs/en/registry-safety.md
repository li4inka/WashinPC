# Registry safety

All scan categories support repair using their category-specific handlers. Expert mode makes additional categories available for scanning and repair. Each repair requires a readable snapshot and a verified backup. Missing means the immediate parent is readable and the target is confirmed absent; permission errors, missing parents and remote/relative paths are unknown.

Each eligible result retains a snapshot of the affected values or the full subtree being changed. Independent value repairs in the same key can be applied together. Before mutation the app verifies the snapshot and missing target, writes a unique UTF-16 `.reg` backup with the original value types, verifies the saved content, then checks eligibility again. Failure blocks that change. This is not a transactional registry engine; a concurrent writer can still race the final check. Use a quiet test system for qualification.

The backup companion file identifies the hive, key and x86/x64 view and gives a view-specific import command. Manual import may overwrite newer values, does not restore ACLs, and is not conflict-aware recovery. Context-menu toggles include value backups with deletion directives for values that were originally absent. Extension deletion does not clean up shared blocked-list entries.

The built-in Backups catalog previews changes, verifies the backup checksum and account, saves the current affected objects, and checks the preview state again before restoring. New copies include versioned JSON metadata; legacy copies use companion view information or an explicit x86/x64 selection. Only listed objects are restored. This remains a sequence of writes rather than an atomic transaction; partial failures are reported. Service copies contain startup configuration and are applied through Service Control Manager, never through a raw `Start` value write. The service category is expert-only, unchecked by default, and limited to stopped own-process services with unambiguous missing EXEs.

A system restore point is attempted before registry fixes. Its failure requires Continue/Cancel; Continue never disables backup requirements. Old backups stay in place. Review the actual target OS qualification in [validation](../validation/README.md).
